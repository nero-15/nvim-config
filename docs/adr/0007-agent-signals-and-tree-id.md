# ADR-0007: Claude の状態通知と、内容で版を特定する検証記録

- 運用の正本: [01-dev-loop.md](../01-dev-loop.md)、[06-operations.md](../06-operations.md)

## 背景

2026-11-10 に、この環境を「エージェントにとっての作業環境（ADX）」と「人にとっての作業環境（DX）」の両面から調べた。足りなかったのは新しいプラグインではなく、次の三つの接続だった。

1. **人はエージェントの状態を見られなかった。** 複数の Claude を並走させられるが、どれが作業中で、どれが許可や回答を待っていて、どれが終わったのかは、各画面を順に開かないと分からない。DNA の「並走するエージェントを見失わない」「人間は判断する」に対して、判断を待たせている場所へ行く手段が無かった。
2. **版を一つの値で特定できなかった。** ADR-0006 は「HEAD の SHA だけで未コミットの内容を保証しない」と決めたが、代わりの特定方法は「差分と未追跡ファイルを特定できる記録を保持する」という手順に留まり、Maker と Checker が機械的に照合できなかった。Check / Verify も HEAD の変化しか検知せず、検証の最中にエージェントが未コミットの編集をしても green と表示していた。
3. **停止条件はエージェントの善意に頼っていた。** `CLAUDE.md` に「green になるまで」と書いてあるだけで、検証せずに終えることを何も止めなかった。逆方向も同じで、エディタで赤を見た人がそれをエージェントへ返すには、ログを手で写す必要があった。

`docs/03-architecture.md` は `.claude/settings.json` を「hook 設定」として挙げていたが、ファイルは存在しなかった。

## 決定

1. **Claude Code の hook でセッションの状態を Neovim へ送る。** Neovim が Claude を起動するコマンドに `--settings scripts/claude-hooks.json` を足し、hook は `$NVIM`（`:terminal` が子プロセスへ渡すサーバーのアドレス）へ `--remote-expr` で通知する。状態は 判断待ち／完了・未読／作業中／待機 の四つとし、ステータスライン・タブライン・一覧・通知に出す。`<leader>aw` で人を待っているセッションへ移る。
2. **版は作業木の内容の tree ID で特定する。** 一時 index に `git add -A` して `git write-tree` した値を使う（`scripts/tree-id.sh`、`make tree-id`）。未コミット・未追跡を含み、同じ内容なら同じ値で、commit しても変わらない。Maker と Checker の報告、`make check` の出力、エディタの Check / Verify の記録に載せる。
3. **検証の前後で ID が違う結果を green としない。** `scripts/verify.sh` は green かつ内容が変わらなかったときだけ検証済みの記録を残し、エディタの Check / Verify は再検証を促す。
4. **このリポジトリに Stop ゲートを置く。** `.claude/settings.json` の Stop hook が、green を確認した内容と違う作業木を残して終えようとした Claude に、同じ内容については一度だけ検証を促す。セッションが何も変えていない場合と、二度目（赤のまま報告する場合）は止めない。SessionStart hook は、開始時の内容が検証済みかどうかを文脈へ渡す。
5. **赤をエージェントへ返すキーを置く。** `<leader>av` が、失敗した実行のログの場所と指示をメインの Claude の入力欄へ入れる。送信は人が行う。
6. **独立した仕事を worktree で始めるキーを置く。** `<leader>aW` が `claude --worktree <名前>` を新しいセッションとして起動する。

## 選ばなかった案

| 案 | 選ばなかった理由 |
|---|---|
| `~/.claude/settings.json` に hook を書き込む | ユーザーの設定を書き換える。Neovim の外で起動した Claude にも効いてしまう。`--settings` は起動したセッションだけに足され、プロジェクトの hook と併用できることを実セッションで確認した |
| ターミナルの画面の文字列から状態を推測する | 表示の変更で壊れる。hook は入力の形式が文書化されている |
| ツール実行のたびに Neovim へ通知する | 通知のたびにプロセスを起こす。判断待ちの間だけ目印を置き、解消されたときだけ通知する |
| `git stash create` や差分のハッシュで版を表す | stash は未追跡ファイルを含めにくく、差分のハッシュは HEAD に依存する。tree ID は内容だけで決まる |
| Stop ゲートで green になるまで終了させない | 直せない赤や、人の判断が要る場面でエージェントを閉じ込める。DNA は「矛盾は止めて報告する」を求める |
| 状態表示のために新しいプラグインを入れる | 必要なのは hook と小さな状態管理で、既存の lualine・snacks で表示できる |

## 影響と限界

- 状態が見えるのは Neovim の中で起動した Claude だけである。起動済みのセッションには反映されない。
- hook・記録ファイル・ゲートは忘れと誤操作を防ぐ補助であり、権限の境界ではない。記録は書き換えられる。Codex には適用されない。
- tree ID の計算は、変更されたファイルの blob を `.git/objects` に書く。参照されないので `git gc` で消える。
- tree ID は ignore されたファイルとリポジトリ外の状態を含まない。
- 「判断待ち」から「作業中」への復帰はツール実行後の通知に頼る。許可を拒否した場合などは、次の区切りまで表示が残ることがある。

## 検証と戻し方

機械検証は [04-verification.md](../04-verification.md) の V-7（`agents-regression.lua`・`workflow-verify.lua`）と V-10（tree ID・Stop ゲート）。実 Claude では、開始・作業中・完了・終了の通知が Neovim に届くことを 2026-11-10 に Claude Code 2.1.321 で確認した。判断待ちの表示と macOS の通知は、人が実画面で確認する。

戻す場合は、`lua/workflow/claude.lua` の起動コマンドから `--settings` と `NVIM_*` の環境変数を外せば状態通知は止まる。Stop ゲートは `.claude/settings.json` の `hooks` を消せば止まる。tree ID は他の機能に依存しないので残してよい。検証条件を緩めて戻したことにはしない。
