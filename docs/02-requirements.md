# 02. 要求仕様

この環境が満たすべきことを ID で管理する。設定変更・ADR・タスクはこの ID を参照する。
受け入れ条件は、なるべく機械で判定できる形にする（[04-verification.md](04-verification.md)）。

優先度: **Must**（無いと DNA に反する）/ **Should**（強く欲しい）/ **Could**（あれば嬉しい）

## 読む（仕様・設計書）

### R-01 Markdown をリッチに表示する — Must
- 見出し・表・コードブロック・チェックリスト・callout（`> [!NOTE]`）を、記号ではなく整形された見た目で表示する。
- 見出しの目次（アウトライン）から任意の節へジャンプできる。
- **受け入れ条件**: `docs/` の任意の md を開くと、表が罫線付きで描画され、`<leader>` 系のキー 1 つで目次が開く。

### R-02 Mermaid 図を見られる — Must
- Markdown 内の ```` ```mermaid ```` ブロックを図として確認できる。
- 最低限: キー 1 つでブラウザにライブプレビュー（保存で自動更新）。
- 理想: ターミナル内でインライン描画（端末の画像プロトコル次第。[adr/0002](adr/0002-terminal-and-image-protocol.md)）。
- **受け入れ条件**: Mermaid を含む md でプレビューキーを押すと、図が描画された画面が開き、保存すると更新される。

### R-03 HTML 設計書を直接見る — Must
- エディタで開いている `.html`（ER 図、構成図、デモ）をブラウザでライブプレビューできる。
- **受け入れ条件**: `erd.html` を開いてプレビューキーを押すとブラウザで表示され、編集すると反映される。

### R-04 仕様・タスクへの一瞬アクセス — Should
- `TASKS.md` / `plans/` / `docs/` / `CLAUDE.md` / `AGENTS.md` に専用キーで飛べる。
- **受け入れ条件**: どのプロジェクトでも同じキーで `TASKS.md`（無ければ `docs/**/tasks.md`）が開く。

## エージェントと協働する

### R-05 worktree を行き来する — Must
- `.claude/worktrees/agent-*` と兄弟 worktree を一覧・切り替えできる。
- ファイル検索・grep は `.claude/worktrees` と `node_modules` を既定で除外する。
- **受け入れ条件**: worktree ピッカーで選ぶとカレントディレクトリが切り替わり、ファイル検索の結果に他の worktree のファイルが混ざらない。

### R-06 停止条件（verify）をエディタから回す — Should
- `make verify` / `pnpm verify` をプロジェクトの種類に応じて実行し、エラーを quickfix / 診断に流す。
- **受け入れ条件**: verify キーで実行され、失敗箇所に `]q` で順に飛べる。

### R-07 エージェントの diff をレビューする — Must
- 作業ツリー全体の変更をファイル単位・hunk 単位で確認し、stage / 取り消しができる。
- Claude Code が提案する diff をエディタ上で受理 / 拒否できる。
- **受け入れ条件**: diff ビューで変更ファイル一覧と差分が並んで表示され、hunk 単位で stage できる。

### R-08 外部変更を即時反映 — Must（既存機能の維持）
- エージェントがファイルを書き換えたら、開いているバッファに自動で反映する。
- **受け入れ条件**: 外部からファイルを書き換えると、1 秒以内にバッファが更新される。

### R-09 Claude Code を扱いやすく — Must
- 選択範囲・ファイルをコンテキストとして Claude に送れる。
- 複数の Claude セッションの切り替え・位置の変更が簡単にできる。

## 操作性

### R-10 画面分割のレイヤーを 1 つに寄せる — Should
- nvim の分割と tmux のペインを行き来するときの操作の揺れを無くす（同じキーで移動・同じ感覚で分割）。
- 方針は [adr/0003](adr/0003-multiplexer-strategy.md)。

### R-11 Vim を学び直せる — Must
- キーを押す途中でガイドが出る（which-key）。
- 非効率な操作（`jjjj` の連打など）に気づける仕組みがある。オン/オフできる。
- 学習の道筋が [05-learning-path.md](05-learning-path.md) にある。

### R-12 vimmer の定番の強機能を入れる — Should
- 使っていなくても、熟練者が愛用する強力な機能は積極的に入れる（テキストオブジェクト、マクロ、quickfix 活用、ファイルをバッファとして編集、複数ファイル一括置換など）。
- ただし入れた機能は必ず which-key と [05-learning-path.md](05-learning-path.md) から辿れるようにする（入れっぱなしで忘れない）。

## 非機能

### R-20 起動が速い — Should
- **受け入れ条件**: `nvim --startuptime` で起動時間が 80ms 以下。

### R-21 壊れにくい — Must
- 外部ツール（linter、formatter、画像ツール）が無くてもエラーを出さず、機能だけが無効になる。
- **受け入れ条件**: `nvim --headless +qa` がエラー出力なしで終了する。

### R-22 再現できる — Must
- `setup.sh` 1 本で新しい Mac に同じ環境を作れる。プラグインのバージョンは `lazy-lock.json` で固定する。
- **受け入れ条件**: `setup.sh` を実行しても `lazy-lock.json` に差分が出ない（専用スクリプトでrestoreと未導入pluginのinstallを行う）。設定ディレクトリの親が無くても止まらず、再実行してもリンクを壊さない。
