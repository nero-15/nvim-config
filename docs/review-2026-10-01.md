### 1. [P1] Verify の相対パスが完了時の cwd で解決される — R-05 / R-06

- 対象: `lua/workflow/verify.lua:68–71, 112–115`
- 実行は開始時の root に固定されるが、quickfix の構築にはその root が渡されない。
- 再現: A で verify を開始し、終了前に cwd を B に変更。A が出力した `src/main.go:1:1: error` の quickfix が B の `src/main.go` を指した。
- 影響: 別 worktree を確認している間に終了すると、別のファイルへジャンプしてしまう。quicker の編集対象も誤り得る。
- 提案: 実行ごとに root を保持し、quickfix のファイルを実行元基準の絶対パスへ解決する。結果のタイトルと context に実行元を記録する。

### 2. [P2] Verify が受信チャンクを完成した行として扱う — R-06

- 対象: `lua/workflow/verify.lua:107–112`
- stdout / stderr のコールバックが受け取るデータは、必ずしも行単位ではない。
- 再現: `printf 'src/ma'; sleep 0.2; printf 'in.go:1:1: chunked error\n'` を出力すると、`src/ma` は無効な項目、`in.go` は別ファイルとして登録された。
- 提案: stdout / stderr ごとに未完の行を保持して改行まで連結するか、完了時に全出力を分割する。両ストリームの断片を直接混ぜない。

### 3. [P2] 新規環境で設定ディレクトリの親が無いと setup が終了する — R-22

- 対象: `setup.sh:27–28`
- `~/.config` または指定した `XDG_CONFIG_HOME` が未作成の場合、最初の `ln -sf` が失敗し、`set -e` で停止する。
- 再現: 一時領域の存在しない `XDG_CONFIG_HOME` に対し、setup の先頭28行を実行して exit 1 を確認。シェル設定変更やインストールには進めていない。
- 提案: リンク作成前に親ディレクトリを作る。すでに正しいリンクならバックアップせずスキップする処理も共通化する。

### 4. [P2] setup が lockfile の復元と更新を混同している — R-22

- 対象: `setup.sh:225`
- `Lazy! sync` は install / clean / update を実行し、更新可能なプラグインを進めて lockfile も更新する。そのため「同じ設定を再現する」セットアップで、追跡済み lockfile の版を維持できない。
- ローカルの lazy.nvim 実装と [公式コマンド仕様](https://lazy.folke.io/usage) を確認。レビュー中に sync や更新は実行していない。
- 提案: セットアップは install と lockfile に基づく restore を使い、update は明示的なメンテナンス操作に分ける。

### 5. [P2] Go lint の存在確認にプラグイン内の識別名を使っている — R-21

- 対象: `lua/plugins/linting.lua:22–25`
- `golangcilint` は nvim-lint の識別名で、実行ファイルは `golangci-lint`。`executable(name)` によりインストール済みでも除外される。
- 再現: 一時 PATH に実行可能な `golangci-lint` を置き、実設定の autocmd と呼び出し記録用の lint スタブを使用。実行可能判定は1だが `try_lint` の呼び出しは0回だった。
- 提案: linter 定義の `cmd` を解決して存在確認する。関数形式の定義・cmd も考慮する。

### 6. [P2] ws が同名ディレクトリを同じ tmux セッションとみなす — R-05 / R-10

- 対象: `aliases.sh:146–147` および `_ws_attach_cmd` / `_ws_switch_in_tmux`
- セッション名が basename だけなので、`client-a/api` と `client-b/api` が同じ `api` に割り当てられる。
- dry-run で両方の attach 先が `=api` になることを確認。既存セッションがある場合、後者を選んでも前者へ接続する。
- 提案: 正規化した絶対パスのハッシュを内部 ID に含める。表示用の短い名前は別に保持する。

## 改修後の検証と改善案

1. **振る舞いを確認するテストを追加する。** 既存スモークはコマンド登録や設定の存在確認が中心。上記の cwd 切り替え、分割出力、空の設定ディレクトリ、実行ファイル名の相違、同名プロジェクトを回帰テストにする。worktree は一時 Git リポジトリを作り2件以上を確認する。
2. **検証結果に対象と鮮度を持たせる。** root・実行コマンド・開始時 HEAD・開始終了時刻を結果に付ける。エージェントが並行して編集するため、終了後にファイルが変わったら前回 green を現在の状態の保証として表示しない。保存を失敗したまま実行する `silent! wall` の扱いも見直す。
3. **初回操作の待ち時間も測る。** 現状の起動時間に加え、最初の Markdown 表示・Spec Hub・worktree 一覧・差分表示を実測する。大量の worktree で待ちが目立つ場合は、一覧作成時の同期 git 呼び出しを非同期化する。
