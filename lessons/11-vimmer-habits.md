# 11 vimmer の習慣 — 自分で調べて、自分で速くなる

> 期間の目安はありません。vimmer とは「全部のキーを知っている人」ではなく、
> **「同じ作業を 3 回したら、もっと良い方法を探しにいく人」** のことです。

## 習慣 1: 不便を感じたら 1 分だけ調べる

| 道具 | 使いどころ |
|------|------------|
| `:help 単語` | 公式ヘルプ。`:help ci"` のように**キーそのもの**でも引ける |
| `<Space>fh` | ヘルプを曖昧検索 |
| `<Space>fk` | この環境のキーマップを検索 |
| `<Space>fc` | コマンドを検索 |
| `<Space>` で待つ | 次に押せるキーの一覧 |

- [ ] `:help text-objects` を開いて、まだ知らないテキストオブジェクトを 1 つ見つけた
- [ ] `<Space>fk` で `Claude` を検索し、Claude 関連のキーを一覧した

## 習慣 2: 悪い癖を数字で見る

`<Space>fH` で、hardtime が記録した「非効率な操作」の集計が見られます。
週に 1 回見て、一番多い癖を 1 つだけ直す。

- [ ] `<Space>fH` を開いて、自分の一番多い癖を確認した

## 習慣 3: 毎日 10 分の練習

| 練習 | 内容 |
|------|------|
| `:Tutor` | 公式チュートリアル（全章をひととおり） |
| `:VimBeGood` | 移動・削除・置換の速さを競うミニゲーム |
| このレッスン | `:LessonReset 3` のようにリセットして、もう一度やる |

- [ ] `:Tutor` を最後の章までやった
- [ ] `:VimBeGood` を 1 回遊んだ（`relative` か `hjkl` から）

## 習慣 4: 上級の道具を少しずつ

慣れてきたら 1 週間に 1 つずつ足してください。

| 道具 | 例 | 何ができるか |
|------|-----|-------------|
| `:g` | `:g/console.log/d` | パターンに合う行すべてに操作（この例は該当行を全削除） |
| `:g` + `:norm` | `:g/^const/norm A;` | 合う行すべてで Normal モードの操作 |
| `:S`（abolish） | `:S/facility{,ies}/school{,s}/g` | 単数・複数・大小文字をまとめて置換 |
| `:cdo` | `:cdo s/old/new/ \| update` | quickfix の全箇所で置換して保存 |
| `g Ctrl-a` | `V` で選んで `g Ctrl-a` | 連番をふる |
| `gv` | — | 直前の選択範囲をもう一度選ぶ |
| `gi` | — | 最後に入力した場所に戻って入力再開 |
| `Ctrl-v` | 矩形選択 → `I` → 入力 → `jk` | 複数行の同じ列に一括入力 |
| `:earlier 10m` | — | 10 分前の状態に戻る（`<Space>u` で変更履歴の木も） |

```text
item
item
item
item
```

- [ ] 上の 4 行を `V` で選び、`:norm A 0` で末尾に 0 を足してから `gv` → `g Ctrl-a` で 1〜4 の連番にした
- [ ] 同じ 4 行の先頭列を `Ctrl-v` で縦に選び、`I- ` → `jk` で全行をリストにした
- [ ] `:g/item/d` で全部消して、`u` で戻した

## 習慣 5: 自分の設定を育てる

この環境もループで育てます（docs/00-dna.md）。不便・欲しい機能があったら:

1. `docs/02-requirements.md` に要求として書く（または Claude に「要求として書いて」と頼む）
2. Claude に実装させる
3. `<Space>vv`（`scripts/verify.sh`）が green になったら完了
4. 判断の理由は `docs/adr/` に残す

- [ ] 使っていて不便だったことを 1 つ、`docs/02-requirements.md` に書いた

## 補助輪を外す

- 1 か月たったら `<Space>th` で hardtime をオフにしてみる。オフでも `jjjj` しなければ卒業。
- `options.lua` の `opt.mouse = "a"` を消してみる（マウスに頼らない練習）。
